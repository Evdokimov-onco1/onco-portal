# Хостинг на имеющихся сервисах: честные границы

11.10.2026 · активы: GitHub `Evdokimov-onco1/onco-portal` и Tilda
(HTTPS-страницы с блоками T123). Новых платных сервисов, VPS и аккаунтов нет —
и этот документ их не предлагает.

## Что уже работает без нового хостинга

Статичная версия портала — клиентский движок `src/`:

- `tilda/T123-year-1.html`, `tilda/T123-year-2.html` — блоки T123, тянут
  `src/portal.js`, `src/portal.css`, `data/orp-data.json` через
  jsDelivr `@main`; материалы `modules/` — через raw.githubusercontent.com;
- всё исполняется в браузере; сохранение результатов в этой версии не
  подключено (`data-results-url` пуст);
- живые блоки на Tilda с этими файлами не сверялись — только сохранённые
  копии в репозитории (см. `tilda/PAGES.md`, `docs/RELEASE.md`).

## Что невозможно с текущими ресурсами

- **`pilot/server.py` + SQLite не запускается ни на GitHub Pages, ни на Tilda**:
  Pages отдаёт только статические файлы (https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages),
  Tilda размещает страницы/блоки, а не пользовательские бэкенды
  (https://tilda.cc/en/answers/a/html-en). Для пилота нужен постоянный процесс Python 3 с
  HTTPS — такого ресурса сейчас нет.
- Не предлагаются обходы: GitHub Actions как постоянный сервер, публикация
  личного Mac через туннель, хранение ростера/ответов ординаторов в публичном
  репозитории, переписывание пилота в клиентский код «как будто» с
  персистентностью.

## Подготовлено (не активировано)

- `tilda/pilot/T123-pilot-entry.html` — выключенная карточка-вход: станет
  активной ссылкой только после вписывания проверенного `https://` адреса
  реально развёрнутого бэкенда (`data-pilot-url`, `data-pilot-enabled="true"`).
- `docs/TILDA_PILOT_RELEASE.md` — чеклист хостинга, авторизации, бэкапов,
  приёмки и отката.

## Важное различие движков

Статичный движок `src/` и пилот `pilot/web` — **разные реализации**. Шесть
записей, встроенный плеер и замечания по границам существуют только в пилоте;
в статичную версию и на Tilda они не перенесены и не заявлены.

## Оставшиеся предпосылки (конкретно)

1. Реальный HTTPS-хостинг для `pilot/server.py` — сейчас отсутствует;
   нужно одобренное место запуска (без покупок это пока не решено).
2. Реальные учётные записи ординаторов/преподавателей вместо демо.
3. Регулярный бэкап SQLite на хостинге.
4. Браузерная приёмка тестерами (плеер, таймкоды, завершение).
5. Только после 1–4: включить `data-pilot-url`/`enabled` и публикация Tilda
   по отдельному поручению.

## Итог

Готовый беззатратный вариант — текущая статичная версия на Tilda+GitHub как
есть. Персистентный пилот — подготовлен к подключению, но требует реального
сервера; его отсутствие — честный блокер, а не скрытая заглушка.
