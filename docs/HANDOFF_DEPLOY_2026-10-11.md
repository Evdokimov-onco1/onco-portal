## Как это работает для ординатора

1. На Tilda нажать «Регистрация» или «Зарегистрироваться».
2. В кабинете Timeweb ввести имя и электронную почту. Самостоятельная регистрация создаёт роль ординатора; права преподавателя самостоятельно получить нельзя.
3. Открыть письмо подтверждения и задать пароль не короче 12 символов.
4. Войти по электронной почте и паролю. Ответы, черновики, тесты и прогресс связаны с постоянным ID аккаунта и сохраняются на Timeweb.
5. Если пароль забыт, нажать «Забыли пароль?» / «Восстановить доступ», открыть письмо и задать новый пароль. Старые сессии после сброса отзываются; ID и учебные данные сохраняются.

## Обновление и откат

1. Работать от актуальной ветки, проверить изменения и тесты.
2. Собрать `python3 deploy/timeweb/build_staging.py`. Архив `deploy/timeweb/dist/staging-package.tar.gz` содержит только явный allowlist; никаких локальных баз и списков пользователей.
3. На сервере проверить точный каталог ONCO. Сделать SQLite online backup трёх текущих баз, проверить `PRAGMA integrity_check`, сохранить конфигурацию. Обычное копирование работающей SQLite недостаточно.
4. Загрузить архив и установщик, сверить SHA256. Использовать `deploy/timeweb/install_staging.py`; на сервере текущая версия загружена под именем `install_auth_staging.py`. Она ограничена точным корнем, проверяет манифест и пути, сохраняет private и создаёт новый релиз.
5. После установки проверить форму входа, публичные auth-ссылки и сохранение тестового черновика только под `stage-student`. Чужие ответы не использовать для smoke.
6. `python3 rollback_staging.py` переключает код на предыдущий релиз, private не перезаписывает. Перед откатом проверить совместимость схемы. Сейчас предыдущий релиз — `release-20261011T130929Z` с работающей авторизацией и исправленным `app.js`.

`enable_auth.py` уже выполнен 11 октября; повторять для обычного обновления не требуется. Синтетические `stage-student` и `stage-teacher` остаются служебными тестовыми аккаунтами. Перенос старого реального ростера и назначение реальных преподавателей — отдельная задача с разрешением владельца.

## Почта

Сейчас используется системный `/usr/sbin/sendmail`, отправитель Timeweb `cl801264@vh464.timeweb.ru`. Письма регистрации и восстановления дошли во «Входящие» согласованного проверочного адреса. Первое техническое письмо первоначально оказалось в спаме; попадание во «Входящие» у всех получателей не гарантируется.

Для следующего этапа можно подключить согласованный служебный SMTP и проверить SPF/DKIM/DMARC. Приложение поддерживает SMTP с TLS; пароли задавать только в серверной конфигурации. Это не повод менять DNS или почту Rotation.

Ссылки подтверждения и восстановления одноразовые, действуют час. Токены хранятся как хэши; в браузере передаются во fragment и удаляются из адресной строки после чтения. Повторный запрос незавершённой регистрации выдаёт новую ссылку. Ответ восстановления одинаков для существующего и неизвестного адреса. Не публиковать письма, токены и журналы с персональными данными.

## Что коллега может докрутить вручную

- Дизайн, тексты и адаптивность Tilda, используя сохранённый архив для сравнения. При вставке T123 использовать готовый файл из репозитория и таблицу ссылок выше.
- Навигацию прежних страниц обоих годов: убрать дублирующие старые входы при их редактировании, не удаляя архив и учебные материалы.
- Согласованный домен кабинета без `staging` — только отдельным изменением: сервер проверяет Host/Origin, одних ссылок недостаточно.
- Реальные назначения преподавателей и групп, служебную почту, резервное копирование по расписанию и мониторинг — отдельные эксплуатационные шаги.
- Проверку видео/таймкодов и учебного маршрута с преподавателем. Содержательные изменения принимает автор программы.
