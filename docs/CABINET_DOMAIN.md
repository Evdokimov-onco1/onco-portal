## Переключение с доступом владельца

1. В Timeweb привязать cabinet.onco-science.ru к существующему корню ONCO, без создания новой учебной базы. Проверить фактические настройки виртуального хоста. Получить нужный IP или целевой DNS-адрес из панели Timeweb; не угадывать его.
2. У DNS-провайдера добавить запись только для cabinet с указанным Timeweb значением. Не менять записи корневого домена, www или почты. Выпустить и проверить HTTPS-сертификат для поддомена.
3. Сделать SQLite online backup трёх баз и копию private/wsgi-config.json по HANDOFF_DEPLOY_2026-10-11.md. Развернуть проверенный пакет интерфейса штатным установщиком. Сохранить прежний релиз.
4. В существующем private/wsgi-config.json заменить только host на cabinet.onco-science.ru, сохранив настройки почты/авторизации. app.py выводит PILOT_HOST и PILOT_PUBLIC_URL из этого значения. Перезапустить WSGI штатным способом. Пути и базы оставить прежними. make_app разрешает один точный Host и Origin; новый адрес нельзя включить одной заменой ссылок.
5. Проверить на новом домене вход служебного аккаунта, черновик после перезагрузки, выход, регистрацию и восстановление синтетического аккаунта, доставку письма с новым адресом, запрет чужого Origin и доступ преподавателя. Аккаунты и прогресс сохраняются, но host-only cookie потребует повторного входа. Старые уже отправленные ссылки регистрации/восстановления могут потребовать повторного запроса.
6. Только после приёмки заменить T123, адреса шапки/подвала и личного кабинета на Tilda. Использовать ?auth=login, ?auth=register, ?auth=forgot на новом домене. Перепубликовать нужные страницы, архив не публиковать.
7. Старый адрес временно оставить с редиректом на новый на уровне отдельного виртуального хоста. Не включать туда второй экземпляр приложения и не ослаблять Host/Origin. Сохранять путь и query; ссылки с fragment-токеном проверять только синтетически, не журналировать токены. Если редирект не готов, убрать старые публичные ссылки и документировать ограничение.
