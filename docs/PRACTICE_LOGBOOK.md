# Письменная практика и преподавательский логбук

Актуально на 10.10.2026. Ветка `feat/practice-logbook`, база `feat/module-learning-content`. Это следующая ступень локального пилота. Tilda, main и прежние версии сайта не менялись. Не заменять прежний пакет при копировании: использовать Git и новую ветку.

## Коллеге: запуск

```sh
git fetch origin
git switch feat/practice-logbook
python3 -m pilot.server --port 8789 --db /tmp/onco-demo.sqlite3
```

Открыть http://127.0.0.1:8789/?module=M01&panel=seminar . При первом запуске создаются демонстрационные аккаунты: student-a / demo-student-a, student-b / demo-student-b, teacher / demo-teacher. Использовать только технические ответы. Базу для длительной работы хранить вне публичного репозитория и отдельно резервировать; `/tmp` выше — временная демонстрация. Привязка только к localhost. Python-сервер не размещается внутри Tilda: для общего доступа нужен отдельно развёрнутый backend и полноценная авторизация.

## Поведение

- В «Семинаре» каждый вопрос имеет письменный ответ, личный черновик, отправку и историю. Текст подчёркивает подготовку к обсуждению с преподавателем.
- OSCE использует задания и чек-листы исходного пакета. Эталон экзаменатора, разбор и рубрика возвращаются студенту после собственного отправленного ответа текущей редакции.
- Tumor Board показывает только доступный этап; следующий открывается после отправки собственного решения предыдущего. Черновик не открывает следующий этап. Разбор и рубрика доступны после последнего этапа. Отправка не означает преподавательский зачёт.
- Преподаватель видит отдельную очередь практики и историю. Семинар: «Обсуждено» / «На доработку». OSCE/TB: «Принято» / «На доработку». Фиксируются преподаватель, дата занятия, комментарий, баллы по критериям; при возврате комментарий обязателен. Критический критерий без полного балла не позволяет принять работу.
- Правка ответа — новая запись; новая попытка ожидает отметки, даже если прежняя была принята. Повтор одинакового запроса не дублирует запись. Новая версия задания не наследует раскрытие эталона; проверка устаревшей работы заблокирована.
- Практика хранится отдельно от клинических ответов через пространство ID `P:`; прежние API клинических задач не позволяют обходить её проверки. Отметки — в SQLite `practice_reviews`.

## Следующий этап

1. Двустороннее завершение модуля: минимальные действия ординатора (лекция, источник, обязательные письменные ответы, полный тест ≥70%), затем подтверждение преподавателем. Сейчас кнопки итогового зачёта нет.
2. Проверить точные видеопривязки с преподавателем; общие архивы не считать конкретной лекцией.
3. Реальная авторизация, роли и назначения, шесть действующих ординаторов, отдельное защищённое хранилище. Персональные данные не помещать в GitHub.
4. Содержательная приёмка отсутствующих OSCE/TB-привязок и виртуальных пациентов. Не добавлять медицинское содержание без основания.
5. Только после приёмки вернуться к архивированию всего старого сайта с сохранением блоков и публикации на Tilda.

Исходные эталоны уже существуют в публичном учебном пакете; ограничение выдачи в пилоте не делает опубликованные ранее JSON/Word секретными. SQLite и демонстрационная авторизация — локальная реализация, не готовая эксплуатационная инфраструктура.
