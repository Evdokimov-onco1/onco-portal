Аудит двух реализаций и план интеграции

Что спроектировал руководитель (пакет V4 от 31.08.2026), что из этого реально стоит на сайте (сборка от 07.09.2026), где расхождения, и в каком порядке их закрывать.

Подготовлено 10.09.2026Источники: локальный пакет, транскрипт разговора, публичный сайт, личный кабинет ординатора, репозиторий данных

Главный вывод. Данные на сайте полностью совпадают с пакетом руководителя (тот же JSON, байт в байт: 61 модуль, 633 вопроса, 12 виртуальных пациентов, 12 станций OSCE, 8 кейсов Tumor Board). Потеряна не база, а интерфейс: исполнительница переписала движок и оставила три вкладки из шести. Виртуальные пациенты, OSCE и Tumor Board лежат в данных, но на сайте недоступны, а карточка модуля урезана до лекции, задач, вопросов и теста.

Вторая проблема глубже: замысел «модуль как единица, в которой сразу видно что читать, какие задачи, какой тест и какие интеграции» не реализован до конца даже в пакете руководителя. Связи модуль → рекомендации, учебники, инструменты и симуляторы есть в данных, но интерфейс их не показывает. Списка «ключевых статей по каждому модулю», о котором говорил Михаил Юрьевич, в архиве нет вообще. Есть только источники к каждому тестовому вопросу.

1. Две архитектуры

Пакет руководителя

ONCO_TILDA_PRODUCTION_PACKAGE_V4, 31.08.2026
  • Один монолитный HTML-блок (1,2 МБ) для вставки в Tilda T123: JSON с данными зашит внутрь, внешних зависимостей нет.
  • Шесть панелей в одном блоке: Модули, Библиотека, Банк тестов, Виртуальные пациенты, OSCE, Tumor Board. Файлы 01–06 отличаются только тем, какая панель активна.
  • Девять маршрутов: /ordinatura (стартовая), /year-1, /year-2, шесть учебных зон, /final-assessment. Глубокие ссылки /ordinatura?module=M07.
  • Полностью рабочие движки: тест с пояснениями, ветвящийся сценарий VP с баллами, станция OSCE с чек-листом, Tumor Board с поэтапным раскрытием.
  • Карточка модуля: лекция, 4 задачи, вопросы для разбора, тест, ссылки VP/OSCE/TB (ID), инструменты (ID).

Живой сайт

Сборка исполнительницы, репозиторий на GitHub от 07.09.2026
  • Данные вынесены в orp-data.json на GitHub (llcbrein-pro/onco-portal) и подгружаются через jsDelivr. Это разумно: контент обновляется коммитом, а не перевставкой мегабайта в Tilda.
  • Раздел закрыт через Tilda Members: группы «Ординатура 1-й год» и «2-й год», страницы /ordinatura-year-1 и /ordinatura-year-2, плюс два «личных кабинета» с лентой видеоматериалов.
  • На странице года три вкладки: Модули (фильтр по году), Библиотека (4 категории, как в пакете), Банк тестов (344 и 289 заданий по годам).
  • Карточка модуля: лекция, задачи, вопросы, кнопка теста, «Закрыть модуль». Без интеграций и инструментов.
  • В репозитории есть версия движка, где VP/OSCE/TB выводятся как сырой JSON в <pre>. На сайт она не попала: этих вкладок нет.
  • Пункт меню «Расписание» никуда не ведёт. Маршруты /ordinatura/* отдают 404.

3. Что скрыто в самом пакете

Эти пункты стоит проговорить с Михаилом Юрьевичем: он уверен, что «в архиве всё подобрано», но часть его замысла до архива не доехала.

  • Ключевых статей по модулям нет. В JSON нет поля со списком публикаций для модуля. Единственные источники: source_title и source_url у каждого из 633 вопросов (в основном ссылки на PubMed-поиск). Из них можно собрать «источники к модулю» автоматически, но это не тот курируемый список, который он описывал. Нужно спросить, в каком файле он его делал.
  • Связи модуль → библиотека существуют, но интерфейс их не рисует. У рекомендаций РФ есть module_ids, у учебников строка modules, у инструментов и симуляторов массивы. Ни в пакете, ни на сайте это не собирается в карточку модуля.
  • Три формата ID модуля. Модули: M09. Вопросы и рекомендации: М-09 (кириллическая М с дефисом). Учебники: строка M04, M09–M10, M57–M59 с диапазонами. Нормализация нужна до любой сборки связей.
  • Инструменты и интеграции показываются как ID. «TOOL-AE-01», «S01», «TB03» вместо названий и переходов.
  • Год лекции и дата. В данных даты 2026–2028 (M61 назначен на 22.04.2028). Это правильно для двухлетнего потока, но требует явного указания на сайте, что это план набора 2026 года.
  • Ограничения Tilda, которые пакет только обещал проверить: выполнение JS в опубликованном T123, высота блока после раскрытия сценариев, iOS Safari, конфликт якорей. Живая версия это уже частично прошла, значит, база рабочая.

4. Чем анализировать сайт без админки

Всё, что ниже, уже применено в этом аудите и годится для повторных проверок.

  • Карта сайта и robots. curl sitemap.xml даёт полный список страниц Tilda, включая закрытые. Так нашлись /main-ordinatura-1 и /ordinatura-year-1.
  • Дамп публичных страниц. Скрипт на Python вытаскивает текст, ID блоков Tilda (data-record-type) и ссылки. По ID блоков видно, из каких стандартных блоков собрана страница.
  • Ваш залогиненный Chrome. Через расширение Claude in Chrome читаю страницы личного кабинета под вашей сессией: текст, дерево доступности, скриншоты, клики по вкладкам.
  • JavaScript в контексте страницы. Один вызов показал, откуда грузятся данные (запрос к jsDelivr в performance.getEntries), какие ID у контейнеров и сколько байт в инлайн-скрипте.
  • Публичный GitHub. Репозиторий исполнительницы открыт: дерево файлов, история коммитов, сам движок. Сравнение JSON с пакетом сделано скриптом.
  • Tilda MCP уже подключён к этой сессии, но отвечает 409: нужны публичный и секретный ключи API проекта. С ними получу список страниц, их HTML и настройки без ручного тыканья.
  • Для регресс-проверки после правок: скрипт на Playwright, который логинится, открывает каждый модуль, запускает тест, проходит один сценарий VP и фиксирует ошибки консоли. Это тот «бот-тестер», о котором вы говорили.

5. План

Рекомендую не откатываться на монолит руководителя, а оставить архитектуру «данные + движок на GitHub, тонкий блок в Tilda», но вернуть в движок всё, что было в пакете, и достроить карточку модуля. Так контент правится коммитом, а Tilda трогается один раз.

Фаза 0. Доступы и контроль

1 день · блокирует всё остальное
  • Ключи Tilda API (публичный и секретный) для MCP, чтобы читать страницы и настройки.
  • Права редактора в проекте Tilda 17587206 и в Tilda Members (группы, участники).
  • Свой репозиторий вместо llcbrein-pro/onco-portal: сейчас сайт зависит от чужого аккаунта. Форк под ваш GitHub, переключить URL в блоке T123, версионировать тегами (@v1.1), а не @main: jsDelivr кэширует ветку до 12 часов.
  • Назначить Михаилу Юрьевичу обе группы Members, чтобы кабинет перестал быть пустым.

Фаза 1. Нормализация данных и связей

1–2 дня · локально, без Tilda
  • Скрипт сборки build-data.py: единый формат ID модуля, разворачивание диапазонов, справочник инструментов и симуляторов по ID.
  • Для каждого модуля вычислить: рекомендации РФ, учебники, инструменты (не больше 3 основных), симуляторы (не больше 2), VP, OSCE, TB, а также «источники к модулю» из вопросов (уникальные title + url).
  • Добавить в библиотеку раздел международных рекомендаций (NCCN, ESMO) и индикалк, как договорились в разговоре.
  • Запросить у руководителя файл с ключевыми статьями по модулям; поле key_articles зарезервировать сразу.
Результат: orp-data.v2.json с готовыми связями, движку не нужно ничего вычислять.

Фаза 2. Карточка модуля как учебная единица

2–3 дня · ядро замысла руководителя

Порядок блоков берётся из пакета: тема, дата лекции, материалы, семинар, клинические задачи, тест, практический навык, связанные ресурсы.

  • Блок «Что читать»: рекомендации РФ и международные, учебники, источники к вопросам, ключевые статьи, всё со ссылками.
  • Блок «Инструменты и симуляторы»: названия, назначение, ссылка, короткая заметка «чему учит».
  • Блок «Практика»: карточки связанных VP / OSCE / TB с кнопкой запуска прямо из модуля.
  • Глубокие ссылки ?module=M07 и #vp=VP-01, чтобы из расписания и рассылок вести в конкретное место.
Результат: открыв модуль, ординатор видит всё, что нужно на неделю, без блужданий по вкладкам.

Фаза 4. Навигация и вход

1 день · Tilda
  • Публичная стартовая /ordinatura из файла 07: маршрут программы, счётчики, кнопки «Войти в 1-й год / 2-й год».
  • Меню раздела внутри блока: 1-й год | 2-й год | Библиотека | Тесты | VP | OSCE | TB | Аттестация. Внешнее меню Tilda: починить «Расписание» или убрать.
  • Переделать вход (кнопка, которую вы назвали кривой): одна кнопка «Личный кабинет», после входа сразу страница года по группе.
  • Преподавательский режим: отдельная группа Members с доступом к эталонам OSCE и чек-листам TB, для ординатора эталон открывается после ответа.
Результат: понятный маршрут для новичка, видео-инструкция не нужна.

Фаза 5. Проверка и гайд

1 день · повторяется после каждого релиза
  • Бот-тестер на Playwright: логин, все 61 модуль, тест по каждому, один проход VP, OSCE, TB, проверка ошибок консоли и высоты блока.

  • Гайд «Как пользоваться разделом» генерируется из скриншотов бота, публикуется на стартовой.
