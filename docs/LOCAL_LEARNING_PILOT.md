## Запуск для коллеги

Из корня репозитория, Python 3.10 или новее, без сторонних библиотек:

```sh
python3 -m pilot.server --port 8789 --db /абсолютный/приватный/путь/pilot.sqlite3
```

Открыть `http://127.0.0.1:8789/`. Сервер слушает только loopback. Если `--db` не указан, используется каталог `onco-learning-pilot` в системной временной папке; ОС может очистить его. Для сохранения работы указывать постоянный приватный путь вне репозитория. Остановка — Ctrl+C. После повторного запуска требуется заново войти, сохранённые ответы и проверки остаются в той же БД.

| Демонстрационный аккаунт | Пароль | Права пилота |
|---|---|---|
| `student-a` | `demo-student-a` | Собственные черновики и отправленные ответы |
| `student-b` | `demo-student-b` | Независимый ординатор для проверки изоляции |
| `teacher` | `demo-teacher` | Все модули назначены этому синтетическому преподавателю |

Эти общедоступные демонстрационные пароли намеренно указаны на странице входа. Они не предназначены для реальных людей, данных или публичного сервера. Не менять bind на 0.0.0.0 и не открывать туннель к этому стенду. Публичный выпуск потребует производственного сервера и настоящей авторизации с утверждёнными назначениями.

## Что работает

- Черновик сохраняется в SQLite и доступен только его владельцу. Он не открывает эталон и не появляется у преподавателя.
- Ответ не может быть пустым; запись подтверждается API. Только после успешной записи API начинает отдавать эталон данной задачи этому ординатору.
- Исправленный ответ — новая запись. Первоначальный ответ, время и история преподавательских решений сохраняются.
- Преподаватель видит очередь последних версий по задачам, историю попыток, может принять ответ или вернуть его с обязательным комментарием.
- Повтор отправки с тем же ключом и содержанием возвращает прежнюю запись. Использование того же ключа для другого текста отклоняется.
- Роль и владелец определяются серверной сессией, а не полями формы. Другой ординатор не может читать чужую отправку, студент не может поставить преподавательскую отметку, проверяющий должен иметь назначение.
- Версия связана с хешем клинических задач модуля: старый ответ не открывает эталон изменённого содержания. Проверка старой редакции блокируется до сверки.
- SQLite-файлы и Python-кэш исключены из Git. Статический HTTP-сервер отдаёт только три файла интерфейса, а не каталог репозитория или базу.

## Границы

- Это демонстрационная авторизация с двумя синтетическими студентами, а не Tilda Members и не реальный список шести ординаторов. В одном браузерном профиле аккаунт общий для вкладок; для одновременной проверки нужны разные профили или HTTP-клиенты.
- Зачётный тест 70% из PR №3 пока не подключён к этой базе. Логбук семинара, OSCE/Tumor Board, видео, обязательные клики и двухстороннее завершение модуля ещё предстоит реализовать.
- Принятие письменного ответа не равно завершению модуля; интерфейс явно это поясняет.
- Клинические материалы и эталоны сохранены из исходного пакета без редакторских изменений. В исходном GitHub/старом портале эти эталоны остаются публичными. Ограничение выдачи в пилоте не делает их секретными во всём проекте.
- История текстов и проверок сохраняется, но архив снимков прежнего содержания задания ещё не реализован. При изменении версии преподаватель не может поставить отметку до сверки.
- Нет автосохранения: черновик сохраняется кнопкой. Несохранённый текст остаётся при переключении задач в открытом модуле; при выходе/смене модуля и закрытии страницы предусмотрено предупреждение.
- Нет боевого TLS, внешнего хостинга, восстановления паролей, эксплуатационного резервного копирования, миграций схемы и публичной регистрации. Встроенный Python HTTP-сервер применяется только локально.

## Проверки

```sh
python3 -m unittest pilot.test_store pilot.test_server -v
node --check pilot/web/app.js
python3 tools/verify_handoff.py
```

Пройдены 23 теста: 14 проверок хранилища и 9 HTTP-сценариев, включая параллельный повтор отправки, изоляцию студентов, назначение преподавателя, защиту от постороннего Origin/Host, ошибку записи, смену версии и перезапуск сервера. Данные интеграционных тестов синтетические, временные БД независимы.

В браузере: сохранение черновика и перезагрузка; отправка M01/C1 и раскрытие эталона; вход преподавателем; запрет возврата без причины; возврат с комментарием; повторная сдача; принятие новой версии; повторный вход после перезапуска сервера с сохранённой историей. Технические ответы явно помечены синтетическими.

Проверка пакета: 131 контрольная сумма, 61 модуль, 633 вопроса; пересборка совпала с V4 кроме даты. Медицинское содержание не проверялось.

Мобильная приёмка пока не подтверждена: браузерный инструмент принял запрос 390 px, но фактический viewport остался 1280 px и мобильный media query не включился. Временная настройка сброшена. CSS содержит адаптивную компоновку, но это не заменяет проверку на телефоне.
