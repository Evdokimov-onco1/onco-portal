# Завершение модуля (двусторонний зачёт)

10.10.2026, уточнение Владимира: **OSCE не обязателен** для завершения. Новый необязательный ответ OSCE не сбрасывает заявку. Изменение самого исходного пакета практики пересчитывает его общую версию.

Актуально на 10.10.2026. Ветка **`feat/module-completion`** поверх **`feat/practice-logbook`** (PR №6 ещё не слит; completion передаётся отдельным PR). Локальный пилот на SQLite; Tilda и `main` не менялись. Публикация на Tilda отложена пользователем; ветки не сливать до приёмки.

## Запуск

```sh
git fetch origin
git switch feat/module-completion
python3 -m pilot.server --port 8789 --db /absolute/private/path/pilot.sqlite3
```

Открыть http://127.0.0.1:8789/ . **Сохранить существующую БД** — миграции добавляют три таблицы, сброс не требуется. Демо: `student-a` / `demo-student-a`, `student-b` / `demo-student-b`, `teacher` / `demo-teacher` (2 ординатора + 1 преподаватель; не шесть резидентов и не боевая авторизация).

## Где нажимать (студент)

1. Вкладка **«Прогресс»**: открыть ссылку на **точную кафедральную лекцию**, привязанную преподавателем к модулю (клик фиксирует открытие, не доказанный просмотр). Клик по той же записи в «Лекция и чтение» тоже учитывается.
2. **«Лекция и чтение»**: открыть **не менее одного актуального** источника из текущего списка модуля.
3. **Клинические задачи**: отправить ответы по **всем** текущим заданиям модуля.
4. **Семинар**: письменные ответы по **всем** вопросам текущей редакции.
5. **Tumor Board**: пройти **все этапы** TB, назначенные модулю (промежуточные письменные ответы обязательны).
6. **Тест**: полный тест модуля по **текущему** банку, **≥70% до округления**.
7. Во вкладке **«Прогресс»** нажать **«Заявить о готовности модуля»**. До выполнения условий кнопка недоступна.

Без **точной** привязанной лекции завершение **намеренно заблокировано** (общий архив или пустая ссылка не подменяют лекцию).

## Где нажимать (преподаватель)

1. Во вкладке **«Клинические ответы»** принять ответы. В **«Логбук практики»** отметить обсуждение семинара и принять финальный этап каждого TB. Промежуточные письменные ответы обязательны, промежуточная оценка по желанию. Это рабочее правило текущего пилота; более строгая оценка каждого этапа отдельно не требуется.
2. В **«Завершение модуля»** выбрать модуль, проверить ссылку на кандидата видео и явно подтвердить привязку. Поле выбирает запись из текущего каталога; произвольный URL сюда не вводится. Выбор не означает автоматической проверки воспроизведения.
3. Раздел **завершения модуля**: при **актуальной** заявке студента — **подтвердить** или **вернуть**; при возврате **комментарий обязателен**.

## Правила (кратко)

- История неизменяема; повторные записи идемпотентны где задумано API.
- Версия заявки учитывает **последние обязательные ответы**; новый ответ инвалидирует старую заявку. Необязательные ответы OSCE заявку не сбрасывают.
- Смена источников, банка или привязок пересчитывает готовность; **фактическое** завершение не выводится только из старого подтверждения в истории.
- Маршруты и логика: `pilot/completion.py`; ограниченное чтение источников для проверки допустимо.
