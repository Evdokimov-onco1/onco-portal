## 0. Жёсткие правила от владельца проекта

1. **Боевые страницы Tilda не трогать без явного «да»** от В.И. Евдокимова на каждое действие.
   Боевые: `/ordinatura-year-1` (page 229315509), `/ordinatura-year-2` (229773709), `/main-ordinatura-1` (130484266),
   `/main-ordinatura-2` (229628509), все публичные страницы.
2. Любые эксперименты — только на тестовых страницах, которые недоступны без точной ссылки:
   закрыты группой Tilda Members, `noindex`, не связаны из меню и с публичных страниц.
3. Перед изменением страницы в Tilda — «Дублировать страницу» (Настройки страницы → Действия). Копия = бэкап.
4. Push в GitHub допустим: боевые страницы от нашего репозитория не зависят. Тестовые страницы читают ветку `main` через jsDelivr (кэш до 12 ч).
5. Клиническое содержание не менять и не «улучшать»: за него отвечает кафедра.

## 2. Как устроено (архитектура)

Решение зафиксировано в `docs/ADR-001-data-and-engine-on-github.md`:

- Вся база — один JSON `data/orp-data.json` (2,6 МБ).
- Один движок `src/portal.js` + стили `src/portal.css`, сам строит разметку.
- В Tilda на странице стоит блок T123 «HTML-код» из ~10 строк: `<link>` на CSS, контейнер с настройками, `<script>` на JS.
  Готовые вставки: `tilda/T123-year-1.html`, `tilda/T123-year-2.html`.
- JS/CSS/JSON раздаются через `https://cdn.jsdelivr.net/gh/Evdokimov-onco1/onco-portal@main/...`
- DOCX-файлы модулей — через `https://raw.githubusercontent.com/Evdokimov-onco1/onco-portal/main/modules/...`
  (jsDelivr отдаёт 403 на DOCX — проверено).

Контейнер и его настройки:

```html
<div id="oncoResidencyPortal"
     data-year="1"                      <!-- 1 | 2 | all -->
     data-data-url="…/data/orp-data.json"
     data-modules-url="…/modules/"      <!-- база для ссылок на DOCX -->
     data-year-2-url="/ordinatura-test-2"  <!-- куда вести модули другого года -->
     data-results-url=""                <!-- приёмник результатов тестов, пока пусто -->
     data-home=""></div>                <!-- ссылка «← Ординатура», опционально -->
```

Движок рисует семь панелей: Модули, Библиотека, Банк тестов, Виртуальные пациенты, OSCE, Tumor Board, Календарь.
Глубокие ссылки: `?module=M07`, `?vp=VP-01`, `?osce=S01`, `?tb=TB01`, `?panel=tests`.
Профиль участника читается из `localStorage['tilda_members_profile' + projectId]` (поля `name`, `login`).

## 3. Данные: откуда что и как пересобрать

`data/orp-data.json` версии `ONCO_PORTAL_DATA_V4` собирается скриптом `tools/build_data.py` из трёх источников:

| Что | Источник | Где лежит |
|---|---|---|
| Модули (61), библиотека, VP (12), OSCE (12), Tumor Board (8) | JSON руководителя V3 от 31.08.2026 | `archive/supervisor-package-v4/ONCO_RESIDENCY_PORTAL_DATA_V3_INTERACTIVE.json` |
| Вопросы (633, с источниками PubMed) | Банк тестов v34 FINAL от 10.09.2026 | `stage6/Tilda_Банк_тестов_FINAL_v34.html` (у Евдокимова, `~/Сайт для МЮ/stage6`) |
| Блок А (рекомендации, обзоры, ключевые исследования, лекции), задачи Б2 с эталонами, чек-листы Б3 | DOCX-модули stage6 → Markdown | `modules/М-NN_*.docx`, md рядом со stage6 |
| Календарь (63 занятия, лекторы, разделы) | `index.html` stage6 | там же |

Пересборка:

```
~/.local/bin/to-md stage6/М-*.docx            # DOCX → Markdown (машина Евдокимова)
python3 tools/build_data.py --stage6 ../stage6
python3 tools/check_data.py                    # 0 висячих ссылок, покрытие модулей
```

Форматы ID модулей в исходниках разные (`M09`, `М-09` кириллицей, диапазоны `M57–M59`); движок и скрипты нормализуют всё к `M09`.
Особенности данных: M40 и M41 стоят в календаре дважды (лекарственная и хирургическая части); у M42–M45 дата «13–14.03.2027».
Даты календаря — проект кафедры, помечены на сайте как предварительные.

Структура модуля в JSON (главные поля): `module_id, pedagogical_year, module_title, actual_lecture_date, lecture, lecturer, section,
calendar[], docx, reading{guidelines, reviews, key_studies, lectures, updates_2026}, clinical_cases[{title, vignette, questions, answer, sources}],
oral_discussion_questions[], skills_checklist[], test_questions, clinical_tools{mandatory, optional, journal}, external_simulators[],
virtual_patients[], osce_links[], tumorboard_links[]`.

## 5. Технические грабли (проверено на практике)

- Tilda API (`getpage`, `getpagefull`) для страниц Members возвращает пустой html. Содержимое блока видно только в редакторе или в браузере под учёткой участника.
- Редактор кода T123 — ACE. Из консоли: `ace.edit(document.querySelector('.ace_editor')).setValue(text, -1)`, затем «Сохранить и закрыть».
- Кнопка «Опубликовать» в редакторе иногда не реагирует на клик; надёжно работает `Cmd+P`. Успех — диалог «Публикация прошла успешно!».
- Экспорт проекта Tilda (zip) содержит только оболочки закрытых страниц.
- jsDelivr кэширует ветку до 12 часов. Сброс: `https://purge.jsdelivr.net/gh/Evdokimov-onco1/onco-portal@main/src/portal.js`.
- Инлайн-стили с селектором `body` в блоке T123 перекрашивают всю страницу Tilda (так сделан старый `Tilda_Банк_тестов_FINAL_v34.html`; его не вставлять).
- В неинтерактивном bash нет `gh`, Homebrew, node; push делает владелец через GitHub Desktop.

## 7. Что не сделано и требует решений

1. **Приёмник результатов тестов**: `data-results-url` пустой, результаты никуда не уходят. Движок шлёт POST JSON
   `{kind, module, score, total, percent, name, email, year, page, completed_at}` в режиме `no-cors`. Нужен Google Apps Script под аккаунтом кафедры или другой приёмник.
2. Стартовая публичная страница `/ordinatura` и страница «Итоговая аттестация» (макеты в `archive/supervisor-package-v4/07_*.html`, `09_*.html`).
3. Ссылки на лекции сотрудников кафедры: в DOCX оставлены пустые места.
4. Клиническая проверка содержания профильным преподавателем — условие основной публикации (README архива stage6).
5. Переключение боевых страниц на новый блок: только после проверки тестовых страниц и явного разрешения владельца.
   Порядок: тег релиза `vX.Y.Z` → заменить `@main` на тег во вставках → вставить в блок боевой страницы → опубликовать → проверить.
6. Локальные коммиты, ещё не отправленные на GitHub на момент передачи: ссылки DOCX через raw, повторная прокрутка к цели глубокой ссылки, записи о бэкапе.
