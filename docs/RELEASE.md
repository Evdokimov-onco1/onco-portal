# Проверка выпуска и откат

Этот файл — порядок будущего выпуска. Подготовка handoff и push ветки не означают публикацию на основных страницах.

## Три разных действия

1. **Push ветки:** файлы становятся доступны коллегам в GitHub. В сохранённых T123 нет ссылки на ветку передачи.
2. **Merge в main:** обновляются адреса с `@main` и `/main/`; тестовые страницы могут получить новую версию после обновления кэша.
3. **Установка/публикация блока Tilda:** меняет конкретную страницу. Выполнять по актуальному поручению владельца после приёмки.

## Перед изменением Tilda

- Открыть фактические настройки обеих страниц и сверить URL, группы, блок T123, код/данные/Word и приёмник результатов.
- Сохранить точный текущий блок, ID страниц, скриншоты и версии. Сделать копию изменяемой страницы и проверить, что её можно использовать для отката.
- Проверить, что резервная копия не даёт случайного доступа к закрытым материалам.
- Выбрать конкретный проверенный commit и релизный тег. Не считать пример v1.0.0 из старого README уже созданным релизом.

## Проверка тестовых страниц

Оба года, обычная учётная запись соответствующей группы, телефон и компьютер:

- модули M01, M24, M33, M46, M61; Word-файлы и переходы между годами;
- тест: выбор ответа, пояснение, источник, окончание и отображение результата;
- семь разделов, библиотека, VP, OSCE, Tumor Board и календарь;
- прямые ссылки и прокрутка после загрузки Members;
- отсутствие ссылок на старый банк; корректные подписи общих видеокаталогов;
- если подключён приёмник — подтверждённая запись контрольного результата и отсутствие передачи лишних данных.

## Установка согласованной версии

Закрепить **все** файлы одной версией: CSS, JS, JSON и база Word. В T123 заменить `@main` на реальный тег/commit, а `/main/modules/` на соответствующий ref в raw URL. Не смешивать новый движок со старой базой. Межгодовые переходы в тестовой паре должны вести на тестовую пару; в основной — на основные страницы.

Установить и опубликовать только указанные страницы, затем повторить ключевой пользовательский маршрут. Зафиксировать commit/tag, время, ID страниц, тип учётной записи и результат проверок. Даты учебного календаря при выпуске не менять.

## Откат

При проблеме вернуть сохранённый блок с прежними адресами и опубликовать ту же страницу либо восстановить проверенную резервную копию. Проверить доступ обеих групп и повторить открытие модуля, Word и теста. Зафиксировать симптом и версию; не удалять старые исходники. Force push и переписывание Git-истории не нужны для отката Tilda.

## Что нужно согласовать отдельно

Редакторский доступ Tilda, изменения групп/ролей, подключение приёмника результатов и расширение аудитории. Статусы из сентябрьского handoff не подтверждают сегодняшний доступ. Архивные инструкции по конкретным кнопкам/горячим клавишам могли устареть: проверять реальный интерфейс.
