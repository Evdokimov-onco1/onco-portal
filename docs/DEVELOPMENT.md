# Запуск и совместная разработка

Нужны Git, Python 3 и браузер. Для проверки синтаксиса JavaScript удобно иметь Node.js; сервер портала от Node.js не зависит. В Windows команды `python3` заменить на доступный `python` или `py -3`.

## Получение этой версии

```sh
git clone https://github.com/Evdokimov-onco1/onco-portal.git
cd onco-portal
git switch handoff/2026-10-04
python3 tools/verify_handoff.py
python3 -m http.server 8787 --bind 127.0.0.1
```

Открыть `/dev/index.html?year=1`, `?year=2`, `?year=all` на http://127.0.0.1:8787 . Остановить сервер: Ctrl+C. Открытие HTML через `file://` не подходит для загрузки JSON. Если порт занят, выбрать другой, например 8788. Для изолированной проверки не вводить персональные данные в браузерные формы; приёмник результатов локально не настроен.

Можно использовать GitHub Desktop: Clone repository → `Evdokimov-onco1/onco-portal`, затем выбрать `handoff/2026-10-04`. После слияния PR основой будет обновлённая `main`.

## Что изменять

| Тип задачи | Основные файлы |
|---|---|
| Интерфейс модуля и прогресс | `src/portal.js`, `src/portal.css` |
| Привязки практики / исходная библиотека | `archive/supervisor-package-v4/ONCO_RESIDENCY_PORTAL_DATA_V3_INTERACTIVE.json` с явным описанием новой редакции |
| Чтение, клинические задачи и чек-листы | соответствующий `sources/stage6/М-*.md`, согласованный Word в `modules/` |
| Вопросы и объяснения | канонический банк `sources/stage6/Tilda_Банк_тестов_FINAL_v34.html`; осознанно оформить новую версию |
| Календарь | `sources/stage6/index.html` и календарный Word; даты без поручения не менять |
| Tilda-вставки | `tilda/T123-year-1.html`, `T123-year-2.html`; установка через редактор отдельно |

`data/orp-data.json` — результат сборки. Ручные исправления только здесь будут потеряны при следующей пересборке. Зафиксировать источник изменения и обновить контрольные суммы изменённых source-файлов в `sources/manifest.sha256.json` после проверки.

## Пересборка без перезаписи действующей базы

```sh
python3 tools/build_data.py --stage6 sources/stage6 --out rebuilt.json
python3 tools/check_data.py rebuilt.json
```

Сначала сравнить результат; `date` меняется на дату запуска. Для принятого обновления после проверки:

```sh
python3 tools/build_data.py --stage6 sources/stage6 --out data/orp-data.json
python3 tools/verify_handoff.py
```

Временный `rebuilt.json` не коммитить. Имена файлов на кириллице не переименовывать ради внешнего вида: проверить соответствие JSON, модульных ID и URL, включая Unicode-нормализацию.

## Работа вдвоём

1. Выбрать одну задачу из TASKS.md и договориться, кто её ведёт.
2. Обновить общую базу и создать отдельную ветку, например `feat/module-sections`.
3. Изменить только необходимые файлы. Запустить проверку данных; для JS — `node --check src/portal.js`.
4. Проверить интерфейс локально на двух годах и экране телефона; приложить к PR краткий результат.
5. Отправить ветку, открыть PR, получить проверку второго участника. Не объединять чужие незавершённые изменения вслепую.
6. Перед merge учитывать, что тестовая Tilda может загрузить новую `main`. Сам merge не заменяет проверку сайта и не подтверждает выпуск на основные страницы.

## Частые затруднения

- «Нет доступных материалов» относится к группам/страницам Tilda Members, а не к GitHub.
- API/экспорт закрытых страниц может вернуть только оболочку. Действующий блок проверять в редакторе и под учёткой участника.
- Для DOCX в этой версии используется raw.githubusercontent.com. Исторически jsDelivr возвращал 403 для этого типа файла; актуальную доступность проверить при релизе.
- Кэш CDN может отдавать прежний файл. Сверять конкретную версию и фактические адреса, а не только дату коммита.
- Новая ссылка на T123 в Git не означает, что блок уже установлен в Tilda.
