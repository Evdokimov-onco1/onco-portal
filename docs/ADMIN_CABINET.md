## Функции

Отдельное право is_admin не смешивает администрирование с ролью преподавателя. Подтверждённый администратор видит список аккаунтов с поиском, статус подтверждения почты и доступ; задаёт роль ординатора/преподавателя, точные модули преподавателя, включает/отключает доступ, читает последние 100 записей журнала изменений. Пароли, хэши, токены, черновики и медицинские ответы не возвращаются административным API. Создание аккаунтов проходит через штатную подтверждаемую регистрацию. Удаления аккаунтов, изменения медицинских текстов и выдачи новых административных прав через интерфейс нет.

/api/admin/overview и /api/admin/users проверяют серверные права; обычный ординатор/преподаватель получают 403. Все POST используют существующую HTTPS/Host/Origin-защиту. Изменение роли/назначений отзывает существующие сессии пользователя через auth_version; новые назначения читаются из SQLite всеми WSGI-процессами. Оптимистичная версия исключает перезапись устаревшим редактором. Администратор не может заблокировать себя или другого администратора. Отключение доступа сохраняет учётную запись и весь учебный прогресс.

## Получение доступа владельцем

Нужен email пользователя, который должен получить административный доступ. Не использовать email аккаунта REG.RU как согласованный email автоматически. Если учётки ещё нет: пользователь регистрируется, подтверждает почту и самостоятельно задаёт пароль штатной формой. После явного назначения владельцем выполнить tools/grant_admin.py --accounts-db <existing-private-accounts-db> --email <confirmed-email> на сервере из принятого релиза. Команда не создаёт пароль и не печатает персональные сведения; выдаёт право только существующей подтверждённой активной учётке с совпадающей почтой. Обновить сессию/войти заново; adminHome открывается автоматически. Логин — email, пароль — установленный самим пользователем. Не выдавать общий пароль в публичном Git или журнале.

## Выпуск

Сохранить online backup трёх текущих SQLite и конфигурацию. Новая схема accounts.sqlite3 аддитивна: admin_grants, admin_settings, admin_audit; существующие accounts/tokens остаются. Собрать пакет штатным build_staging.py (admin.py/admin.js добавлены в allowlist), проверить манифест, установить штатным установщиком. Конфигурация mail/Host/DNS не меняется. tools/grant_admin.py — только серверная утилита, не публичный ресурс и не часть автоматически исполняемой установки.

Прежний код не учитывает admin_settings (включая отключения/назначения), поэтому после применения административных изменений откат на старый релиз требует сначала остановить публичный доступ и согласовать права. Не обещать безопасный автоматический откат с сохранением ограничений на старую версию. Базы поверх новых учебных записей не перезаписывать.
